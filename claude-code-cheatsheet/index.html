Source of truth. Names, descriptions, aliases and argument hints were parsed directly out of the command registry inside ~/.local/share/claude/versions/2.1.220, not from published documentation. CLI commands and flags come from claude --help on the same build.

Defined is not the same as available. Being compiled into the binary does not mean a command is reachable. The terminal CLI builds its registry from a list with conditional entries, so a command can exist in the bundle and still never be registered — typing it returns Unknown command, which is a different failure from a registered-but-gated command's isn't available in this environment. Eleven entries here are in that state and carry a not in terminal CLI tag; hover it for the reason. Most are Artifact- and Desktop-oriented skills that other hosts register. /skill-doctor is the interesting one — it is withheld by the tengu_lantern_prism feature gate and does run if you set CLAUDE_CODE_LANTERN_PRISM=1.

That claim was tested, not inferred: each command without supportsNonInteractive was probed against build 2.1.220 and classified by its response. Commands that could actually execute were excluded from the probe rather than run.

Where the links go. Each command name links to the most specific page that explains it on code.claude.com/docs — a dedicated feature page where one exists, otherwise the official commands reference or the bundled-skills section. Every destination was checked against the published documentation index. A name shown without a link has no official page: those are internal or undocumented entries that exist only in the build.

Build and docs disagree in places. This index follows the binary, so it includes commands the documentation does not cover, and omits /deep-research, /pr-comments and /verify, which the docs list but this build does not register. /vim is likewise absent — in 2.1.220 vim is an editor-mode setting, not a command.

Availability varies by context. Many commands are gated on an interactive terminal session, a feature flag, your plan, or environment variables — entries carry a conditional tag where that gating is explicit in the build. Hidden entries are internal and do not appear in /help.
