/bundled skills — the prompts, in full

Claude Code ships with skills that are nothing but prompts. When you type /doctor or Claude reaches for dataviz, what actually happens is that a block of text gets pushed into the context window. This page is that text — every bundled skill in build 2.1.220, read out of the shipped binary and reproduced in full, so you can see exactly what the model is being told before it answers you.

0Bundled skills Registered inside the binary itself, not in ~/.claude/skills. The command index counts 23 of these because it only lists the ones that reach the slash-command menu on a default terminal build.
0Words of prompt The whole corpus, reproduced below. Longest is claude-api; shortest is design.
0Shipped as whole SKILL.md files Stored complete, frontmatter and all. The rest are built at run time from constants, joined section arrays, or builder functions.
0Registered conditionally Present in every copy of the binary, but they appear only when an isEnabled check passes — a feature flag, an entry point, a login. The flag name is listed where the check names one outright.

How this was read

Claude Code is distributed as a single Bun-compiled executable with its JavaScript bundle embedded verbatim. Every bundled skill is registered in that bundle by a call carrying the skill's name, the description the model sees when deciding whether to invoke it, and a getPromptForCommand function that returns the prompt. The extractor reads the binary as text, locates those calls, and resolves each prompt back to its source string.

Prompts arrive by four routes, and each entry below says which one it took. A whole SKILL.md shipped as a module export is reproduced byte for byte, and so is a single string constant. A joined section array is concatenated in the order the skill joins it. A builder function stitches literals around values known only at run time — those are marked assembled.

Where a prompt interpolates something, you will see ${…}: a value this page cannot know, because it depends on your repo, your model, or your session. Where the interpolation was itself a choice between two phrasings, both phrasings are shown, so an assembled prompt occasionally reads as two sentences run together where the running CLI would pick one. Everything shown is text the binary really contains. Nothing is paraphrased, and nothing was produced by executing the program.

The extractor is checked in at build/claude-code-built-in-skills/extract_skills.py — point it at your own copy of the binary to reproduce this page.
