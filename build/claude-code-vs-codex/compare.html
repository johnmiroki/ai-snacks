Claude Code vs Codex CLI

Two terminal coding agents, command for command. Where both do the same job, this page puts them side by side and quotes each tool's own description of itself rather than paraphrasing either. The shape of each surface

Same job, two very different places to type it

Before any single command: the two tools disagree about where a coding agent's controls belong. Claude Code puts them at the prompt, behind a /. Codex puts them in your shell, as subcommands. That one choice explains most of the differences further down — including why Codex needs 68 subcommands and Claude Code needs 14.

A gated tag means the command is compiled into the build but registers only when a check passes, so it may not exist in your copy — type it and Claude Code answers isn't available in this environment rather than running it. One row is weaker than the others, and it is the hooks row. Both binaries carry the same eleven event names. For Claude Code that settles it — they are the keys its settings.json takes. For Codex it does not: Codex also ships /import, which imports a Claude Code setup, so it has a reason to know those names whether or not it fires all of them. Which one to reach for

The opinion section, marked as such

Everything above this line is measured. This part is not — it is a reading of those measurements, and someone who weighs sandboxing against session ergonomics differently would write it differently. Both tools are good. The question worth asking is not which is better but which set of assumptions matches how you work.

Where the two halves came from. The command comparison is built from the same two inventories as the index pages on this site, and adds nothing to them: Claude Code's names and descriptions were parsed out of the installed binary, Codex's were read off the running / picker and a recursive walk of codex --help. Descriptions are reproduced as the builds carry them. Every name links back to its full entry.

The pairing is editorial; the complement is not. Which two commands count as “the same job” is a judgement made by hand, and the reason both descriptions are printed is so that judgement can be checked rather than trusted. The two only in lists are then computed as whatever no pair claimed — so a bad pairing shows up as a missing entry, and every command in both inventories appears exactly once on this page.

The capability table was measured on one machine. Sandbox modes, approval policies, config paths and provider options come from claude --help and codex --help on the builds named above, plus the shape of the files in ~/.claude and ~/.codex. Where a claim could not be established that way it is marked rather than rounded off — see the note under the table.

Two builds, one moment. Both tools ship fast, and both resolve part of their surface at run time: Codex against 100 feature flags and your account, Claude Code against its own gating. A count here is the count on these two builds, not a permanent fact about either tool.
